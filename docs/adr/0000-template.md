# ADR-0000: Short decision title

- Status: proposed
- Date: YYYY-MM-DD
- Owners: @owner
- Related issues/PRs: link

## Context

Describe the user need, current constraints, security boundary, scale requirement, and evidence.
State which facts are known and which assumptions require validation.

## Decision

State the chosen behavior precisely, including public interfaces, data ownership, failure mode,
compatibility range, and rollback boundary.

## Alternatives considered

List realistic alternatives and why each was not selected. Include the option to keep the current
design.

## Consequences

Describe benefits, costs, operational work, security impact, migration, observability, and limits.

## Validation

List tests, feasibility gates, benchmarks, and acceptance evidence required before rollout.

## Rollback or supersession

Explain how to reverse the decision safely or what a replacement ADR must preserve.
